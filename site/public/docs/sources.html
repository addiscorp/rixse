Sources

A source adapter explains the data and runs a query. Rows stay in the app and never pass through the model.

Source contract

defineSource({ describe, query?, run, hint? }) defines an adapter. describe gives the agent schema and query guidance; query is a short label for the query language; run(query) returns rows; hint(error) can turn a backend error into a useful correction.

import { defineSource } from 'rixse/ui';

const source = defineSource({
  describe: 'Movies queried in ZQL. Movie has title, year, gross.',
  query: 'ZQL returning Movie rows',
  run: (query) => [{ query }],
  hint: (error) => error
});

Connect a component to the adapter with its source name, then register the adapter in createViewport({ components, sources }). The viewport runs queries and gives returned rows to the renderer.

Worked example: zega + Movies

The Movies demo registers a zega source. Its schema includes Movie (title, year, gross, cast, directors, genres), Person and Genre. ZQL follows relationships with arrows and can filter across them.

This self-contained adapter uses one local row so the example runs without a Zega service. The Movies demo’s zegaSource runs ZQL through its Zega engine and supplies schema text and query corrections.

import { createViewport, defineComponent, defineSource } from 'rixse/ui';

const zega = defineSource({
  describe: 'Zega Movies: Movie(title, year, gross); Person; Genre.',
  query: 'ZQL: { Type(filter) limit N { fields } }',
  run: (_query) => [{ title: 'Avatar', year: 2009, gross: 1 }],
  hint: (error) => error
});
const movie = defineComponent('table', {
  describe: 'Movie detail', sizes: ['medium', 'large', 'viewport'], source: 'zega'
});
const viewport = createViewport({ components: [movie], sources: { zega } });

A real Movies query for yearly gross is:

{ Movie(title = "Avatar" || title = "Titanic") limit 100000 { title year gross } }

The query returns rows to the local renderer. The agent chooses the query and component parameters; it does not receive the rows.
