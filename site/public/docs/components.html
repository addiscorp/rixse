Components

Components are the agent’s visual vocabulary. The renderer owns pixels; the agent picks a kind, data query, parameters and size.

Define the vocabulary

defineComponent(kind, def) returns a component specification. Its definition names the supported sizes, optional default size, parameters, source, identity fields, selection description and optional row check.

import { defineComponent } from 'rixse';

const bar = defineComponent('bar', {
  describe: 'Compare amounts across things.',
  sizes: ['medium', 'large', 'viewport'],
  source: 'zega',
  identity: ['query'],
  params: { label: { type: 'string' }, value: { type: 'string' } }
});

The size ladder

viewportfills the container
large2 columns × 2 rows
medium2 columns × 1 row
small1 column × 1 row

Large, medium and small keep the same shape on each platform. A viewport fills the container and owns its contents. Components declare which sizes they support; the Movies line supports large and viewport, while a bar supports medium, large and viewport.

Layout follows the container

layout(state, width, bands?) is a pure function. It picks a column count from width bands, then maps the state’s ordered items to cells. Width is the viewport container width, not the device screen width.

import { layout } from 'rixse';

const state = { items: { top: { size: 'large' } }, order: ['top'], selection: null };
layout(state, 800, [
  { min: 0, cols: 2 },
  { min: 720, cols: 4 },
  { min: 1280, cols: 6 }
]);
// { cols: 4, cells: [{ id, cols, rows }, ...] }

Ensure by identity

A component may name identity fields, such as ['query']. When a component with the same kind and identity already exists, view.show rejects the duplicate and tells the agent to reuse the existing id. Reusing that id updates the component in place. This is ensure-by-identity in the current viewport API.

Draft status: APS 4 PR #5 is open and describes the proposed size and identity direction. It is a draft, not a settled APS entry. This page describes the merged implementation.
