Selection & voice

Selection is state. It tells the agent what the user is pointing at and gives spoken words such as “these” a concrete referent.

Selection is shared state

A renderer reports a click through select.set; clearing uses select.clear. The selection is included in the viewport state and can also be attached to the user’s message:

The user has selected: Avatar (movie), Titanic (movie).

That sentence makes “these” explicit in the prompt. APS 2 PR #3 describes this as a proposal and remains an open draft.

Voice and deixis by timestamp

The iOS voice input records each selection change with a timestamp while the microphone is open. Speech recognition supplies word timestamps. pairDeictics(words, timeline) pairs words such as “this”, “these”, “she” and “them” with the selection in effect when each word was spoken, then the message includes those pairings. It avoids using only the final selection after the utterance.

import Foundation
import Rixse

let firstSelection = Selection(view: "top", items: ["Avatar"])
let secondSelection = Selection(view: "top", items: ["Titanic"])
var timeline = SelectionTimeline()
timeline.record(firstSelection, at: 0.8)
timeline.record(secondSelection, at: 2.1)
let pairings = pairDeictics(
  words: [SpokenWord("these", at: 2.3)],
  timeline: timeline
)

The iOS voice bar

The Movies iOS app has a floating mic bar. Tap-to-talk ends after silence; holding sends on release. A transcript chip can be corrected before sending, and a long press opens the keyboard. Voice stays attached to the same selection and action state as touch input.

Draft status: APS 6 PR #7 is open and proposes timestamp-based pairing and voice-first phone behavior. It is still a draft; the current Swift implementation is the reference for shipped code on main.
