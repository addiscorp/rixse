Overview

A small shared state gives the user and the agent one clear way to change an interface.

ui = agent(schema, view(state), prompt)

The prompt says what the user wants. The schema describes the components and their data. view(state) is the current interface as structured state, not a DOM snapshot. The agent proposes typed actions from that vocabulary; rixse validates and applies them, and the renderer draws the new state.

Inputsprompt + schema + view(state)

One stateuser and agent actions are recorded
→
UIview(state), rendered for its platform

The mental model

  • State is the current set of components and selection.
  • View deterministically renders that state.
  • Agent proposes typed actions; it does not write pixels or markup.
  • Schema is the component catalogue and source descriptions that define valid actions.
  • Prompt is the user's intent, with current selection attached when relevant.

The store records each applied action with its author (you or agent), payload and optional reason. A rejected action returns a reason. Undo restores the prior state.

The governing APS 2 proposal describes the founding rule. APS 1–2 PR #3 is still an open draft; the merged code on main is the source of truth for what exists today.

See one turn

The Movies demo starts with a top-10 box-office bar chart. The user selects two bars and asks “compare these over the years”. Here is what the system passes and what changes.

01 · Prompt

“compare these over the years”

Input also carries: The user has selected: Avatar (movie), Titanic (movie).

02 · Schema

Components: stat, bar, pie, line, table, graph. Sizes: viewport → large → medium → small.

Movies: title, year, gross, plus cast, directors and genres relationships. The source describes ZQL.

03 · view(state)

Current view: a top-10 box-office bar chart. The agent receives its typed component state and the selected bars, not chart pixels.

04 · Agent actions

One typed action changes the bar view into a line view:

view.show({
  id: 'gross-over-time',
  kind: 'line',
  title: 'Box office over time',
  query: '{ Movie(title = "Avatar" || title = "Titanic") limit 100000 { title year gross } }',
  label: 'title', x: 'year', value: 'gross', size: 'large'
})

≈92 output tokens for a full chart turn in the iOS log

The compact count is an observed demo turn; model and prompt change token usage.

05 · State → UI

The store applies the action. The query returns movie rows to the app, and view(state) renders their yearly grosses as a line chart. Layout and rendering are deterministic on web and iPhone.

What this buys

  • Typed and attributable: the agent chooses only allowed actions. It never draws pixels, and the log records who changed what.
  • Small outputs: a few action fields describe a chart update, which keeps the response quick and inexpensive.
  • One state, multiple renderers: the same state and layout rules drive web and native Swift; shared conformance vectors check the core behavior.
  • Shared control: a user click and an agent proposal update the same state through the same action vocabulary.
