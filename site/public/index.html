The page loads. The model doesn’t.

Starting with a configured top-10 view, the source returns rows and view(state) renders locally—zero model requests.

Use ← / → keys, Back / Next, or a step marker.
All six stages
  1. Load. The source and view render locally; no model call.
  2. Use. Select, hover or filter; state and UI change locally.
  3. Ask. “compare these over the years” starts one model request.
  4. Send. Schema, view summary, selected names and prompt leave the app; source rows stay.
  5. Receive. The model proposes a typed view.show action.
  6. Apply. The app validates the query, updates state and renders real points locally.

The model returns a typed action

view.show({
  id: "v1", kind: "line",
  title: "Box office by release year",
  query: '{ Movie(title = "Avatar" || title = "Titanic") limit 100000 { title year gross } }',
  label: "title", x: "year",
  value: "gross", size: "large"
})

About 92 output tokens for a compact chart action; an approximate, model-dependent size, not a measured call on this page.

The wire response is JSON: {"view.show": {…}}, alongside a short say reply. It specifies a component and a query—not pixels or executable UI code. The app resolves v1 to the existing chart.

People and agents shape the same interface through the same typed actions.
