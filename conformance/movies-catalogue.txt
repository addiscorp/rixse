Components (sizes: viewport = the whole width, large = a big tile, medium = a wide tile, small = a small tile; * marks the usual size). The page lays them out; you choose kind, params, size and where it goes relative to the others.
- stat [small*|medium] reads zega: ONE number shown large: how much, how many, what year. Several rows are summed (or as the value says).
    params: label?: string (field path naming each bar/slice/series, e.g. "title", "name"); value?: string (field path or sum|count|avg|max|min(path), e.g. "gross", "sum(movies.gross)", "count(acted_in)")
- bar [medium*|large|viewport] reads zega: compare amounts across things (box office, counts); use limit, e.g. 10–20.
    params: label?: string (field path naming each bar/slice/series, e.g. "title", "name"); value?: string (field path or sum|count|avg|max|min(path), e.g. "gross", "sum(movies.gross)", "count(acted_in)"); sort?: string ("value desc" (default), "value asc" or "label asc"); limit?: number = 0 (keep the first N after sorting)
    select: bar labels, "Avatar|Titanic"
- pie [medium*|large] reads zega: shares of a whole; shows 7 slices plus Other.
    params: label?: string (field path naming each bar/slice/series, e.g. "title", "name"); value?: string (field path or sum|count|avg|max|min(path), e.g. "gross", "sum(movies.gross)", "count(acted_in)"); sort?: string ("value desc" (default), "value asc" or "label asc"); limit?: number = 0 (keep the first N after sorting)
- line [large|viewport*] reads zega: change over time (years): series are labels, x a year path, value summed per year. The chart computes and flags the big changes itself.
    params: label?: string (field path naming each bar/slice/series, e.g. "title", "name"); value?: string (field path or sum|count|avg|max|min(path), e.g. "gross", "sum(movies.gross)", "count(acted_in)"); limit?: number = 0 (keep the first N after sorting); x: string (the x-axis field path, e.g. "movies.year"); flag?: "none"|"drops"|"rises"|"both" = "none" (mark the biggest drops/rises); threshold?: number = 0 (minimum change in percent to flag (default 25)); notes?: string (context at x values, "2020:Theaters close|2012:The Avengers opens" (words only))
    select: a year, "x:2019"
- table [medium|large*|viewport] reads zega: detail rows.
- graph [large*|viewport] reads zega: how movies and people connect (shared cast, a director’s films).
    select: nodes and edges, "person:Name|movie:Title|person:Name > movie:Title"
## Source "zega"
The movies database, queried in ZQL (-> points out of a type, <- points in):
schema {
  type Movie {
    qid: String
    title: String
    year: Int
    gross: Int
    cast: CAST -> Person[]
    directors: DIRECTED -> Person[]
    genres: TAGGED -> Genre[]
  }

  type Person {
    qid: String
    name: String
    acted_in: CAST <- Movie[]
    directed: DIRECTED <- Movie[]
  }

  type Genre {
    qid: String
    name: String
    movies: TAGGED <- Movie[]
  }
}

ZQL, the read queries you may write:
- Shape: { Type(filter) limit 100000 { field field } }. Always add "limit 100000" (it covers every row) after a list filter; a filter of only equality tests means exactly ONE node.
- Tests: = != > < >= <=, &&, ||, parentheses. Text: field findLike "x" (case-insensitive substring; prefer it for names and titles).
- Follow a relationship inside the braces with its own arrow: { Movie(title findLike "Titanic") limit 100000 { title cast -> Person { name } } } and { Person(name findLike "Tom Hanks") limit 100000 { name acted_in <- Movie { title year } } }.
- Filter across a relationship with has: Movie(has cast(name findLike "Tom Hanks") && has cast(name findLike "Meg Ryan")). has genres(name findLike "animated").
- There is NO sort, count, sum or group in ZQL: fetch the rows and let the component do it with value ("sum(movies.gross)", "count(acted_in)"), sort and limit. Rows with the same label are grouped and summed.
